# TCS document research

The existing Research screen now calls FastAPI through same-origin Next.js proxies. It uses Gemini with a configurable server-side key and model, local PDF text extraction and BM25 passage retrieval. No vector database, embeddings service, agent framework, web-search tool or AI alerts are involved.

## Configure and run

1. Create a key in [Google AI Studio](https://aistudio.google.com/apikey). The default `gemini-3.1-flash-lite` model currently has a [free tier](https://ai.google.dev/gemini-api/docs/pricing); availability and quotas depend on the project/region. FINN does not enable billing or switch to a paid provider automatically. Google may use free-tier inputs to improve products; each request sends the question and retrieved public excerpts to Gemini.
2. Copy `backend/.env.example` to `backend/.env` if that file does not already exist. Set:

   ```dotenv
   GEMINI_API_KEY=your_key_here
   FINN_RESEARCH_MODEL=gemini-3.1-flash-lite
   ```

3. Install updated dependencies: `backend/.venv/bin/python -m pip install -r backend/requirements-lock.txt`.
4. Restart `npm run dev:backend`, then run `npm run dev` as usual and open `/research`. Click **Refresh connection** if the page was already open. Process environment variables take precedence over the file. Never use `NEXT_PUBLIC_` for the key. `.env` files are ignored by Git.
5. Optional preparation before opening the page: `backend/.venv/bin/python scripts/prepare_research.py TCS`. Initial extraction takes about a minute; subsequent starts read the disk index.

## Verified sources

`data/research-companies.json` contains curated, versioned document metadata and discovery URLs:

- **TCS Annual Report 2025–26**, 361 physical PDF pages, from the official BSE filing linked in Screener's Annual Reports section. The TCS website returned HTTP 403 for direct downloading in this environment, so this is the exchange-hosted copy.
- **TCS Q2 FY 2026–27 earnings-call transcript**, 29 physical PDF pages, call held 8 October 2026, filed on NSE on 14 October 2026. The link was verified against the real announcement feed.

Original PDFs and extracted page chunks are stored under `backend/.cache/research/`. Metadata records the source URL, SHA-256 checksum and indexing timestamp. Cache keys include document metadata, so changing a document URL/version selects a new index. Reports are a pinned corpus; they are not silently described as continuously updated. To rebuild an unchanged document, remove its cached JSON/PDF and restart the backend. No fabricated reports or cached model answers are used.

## Answer flow and limits

The server extracts text page by page using pypdf with fontTools decoding. Chunks overlap within each physical page. BM25 ranks relevant passages; explicit annual-report/transcript questions restrict document type. Up to eight passages, with source names and periods, go to Gemini. Financial units, periods and standalone/consolidated distinctions must be preserved; ambiguous tables should cause abstention.

Gemini returns structured claims with evidence IDs. The server rejects missing citations and unknown passage IDs. Citation names, URLs, physical PDF pages and complete supporting excerpts are constructed directly from the trusted index, never generated by the model. This avoids model quotation/paraphrasing errors; whitespace and Unicode ligatures are normalized. Each displayed claim links to its evidence excerpt and original PDF page. The model is instructed to treat document text and user requests as data, ignore embedded instructions, and use no outside knowledge.

Absent evidence produces an explicit insufficient-information response. This means the retrieved evidence could not answer the question, not that the information necessarily appears nowhere in the full report. Valid source IDs are not a semantic proof of every model claim; users should verify citations. Charts/images are not OCR'd. Twenty annual-report pages have little or no extractable text, visibly disclosed in the source panel; all transcript pages have searchable text. PDF page numbers include the filing cover and may differ from printed labels.

A failed evidence check gets one corrective model retry using the same passages; a second failure is shown as an error. Missing keys, download/extraction failures, invalid model responses, timeouts and Gemini quota/authentication errors produce visible errors, with no demo answers. At least one document must index successfully; missing document types and failed downloads are disclosed. This is a local single-worker prototype, not an authenticated public service.

## Extend to another company

Add a symbol/name and its curated document entries to `data/research-companies.json`, using unique document IDs and official PDF URLs. Run `scripts/prepare_research.py SYMBOL`; `/api/research/status?symbol=SYMBOL` and `POST /api/research/ask` use the same generic backend logic. Enable that company in the frontend selector when its sources are ready. The selector now accepts other NSE tickers on demand.

## Endpoints and checks

- `GET /api/research/status?symbol=TCS`: source inventory, readiness and key-configured boolean; never the key.
- `POST /api/research/ask`: JSON `{ "symbol": "TCS", "question": "…" }`, up to 1,000 characters. Returns cited claims or explicit insufficient evidence. The same paths are exposed by Next.js.
- `backend/.venv/bin/python -m pytest backend/tests/test_research.py -q`: deterministic guardrail, retrieval, PDF and API tests with an injected model provider.
- `backend/.venv/bin/python scripts/smoke_research.py`: two live questions through Next.js (up to two Gemini calls per question), checks a sourced answer and refusal to invent a future number. Requires both local servers and a configured key.

## Multi-company extension

The company field now accepts a company name from the suggested portfolio list or any NSE ticker. Use **Load sources** to retrieve documents on demand. TCS retains its verified curated corpus; INFY, RELIANCE, HDFCBANK, PERSISTENT and other tickers use Screener's document directory to discover exchange-hosted primary PDFs. The directory's NSE identity must match the requested ticker. Only the newest eligible annual report and transcript are selected; their source periods are displayed. Missing or blocked documents are reported, and available documents can still support research.

Discovery metadata is cached on disk for 24 hours and reused in memory for the running process. PDFs and page indexes reuse the existing content-location cache across restarts. Restart to recheck expired discovery metadata. No portfolio-wide prefetch occurs. Name suggestions cover the existing company list; other companies can be entered by ticker. Source access and coverage depend on the public directory and exchanges; unavailable tickers never use another company's documents. Alerts are unchanged.

Verified extension: 25 targeted research/discovery tests and TypeScript checks passed. Live Infosys and Persistent research each returned answers with three source citations. Annual reports and transcripts were retrieved and indexed for both.
